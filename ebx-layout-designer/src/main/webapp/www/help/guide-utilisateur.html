Layout Designer : guide de l'utilisateur

Le Layout Designer met en page la fiche d'une table EBX par glisser-déposer, sans code ni compilation. Il est réservé aux administrateurs. Les utilisateurs métier n'en voient que le résultat : la fiche de la table.

1. Commencer une mise en page

Depuis la liste des mises en page : la page Mises en page de fiches (dataset LayoutDesigner, table Mises en page de fiches, Actions › Record form layouts, ou son entrée dans une perspective) liste les mises en page enregistrées : table, modèle, version, état, dernière modification. Ouvrir le designer en ouvre une sur un dataset de son modèle.

Pour en commencer une nouvelle, choisissez l'espace de données et le dataset avec les sélecteurs d'EBX (arbre et recherche), puis la table (la liste suit le dataset choisi), puis Continuer.

Depuis la table elle-même : ouvrez la table, Actions › Design the record form.

La première fois, le designer propose une mise en page de départ construite depuis le modèle : un onglet Général avec un panneau par groupe du modèle (deux colonnes), les champs hors groupe dans un premier panneau, et un onglet par association. C'est un brouillon tant que vous ne l'enregistrez pas.

2. L'écran

3. Construire la fiche

  • Onglets : + Onglet, glissez un onglet pour le déplacer. L'inspecteur règle son libellé (un par langue) et un compteur : la somme des lignes des associations cochées, affichée dans le titre (« Commandes (5) »).
  • Lignes : + Ligne à 1 colonne ou à 2 colonnes, en proportions 1:1, 2:1 ou 1:2. Sous 900 px, une ligne à deux colonnes s'affiche sur une seule, colonne de gauche d'abord.
  • Champs : glissez un champ dans un panneau ; posé sur une colonne vide, il crée un panneau autour de lui. Par champ : un libellé propre à cette fiche (vide = le libellé du modèle, traduit par EBX), un widget, la lecture seule, le libellé au-dessus sur toute la largeur. Un champ obligatoire absent de la fiche est signalé : la création d'un enregistrement échouerait sans lui.
  • Associations : glissez-en une pour poser sa grille.
  • Blocs : glissez depuis la palette ; posé entre deux lignes, un bloc ouvre une nouvelle ligne ; posé sur un onglet, il part à la fin de celui-ci.
  • Chaque modification dit ce qu'elle a fait (« le panneau X a été créé autour de Y ») et Annuler la défait.

Widgets d'un champ

Texte, texte sur une ligne, zone de texte, nombre, date, case à cocher, Oui / Non (radio), liste déroulante, liste sans « Créer » (clé étrangère), boutons radio. Formes d'affichage en lecture seule : chiffre mis en avant, pastille, lien, code (police fixe). Sans choix, c'est le widget d'EBX qui s'applique.

Deux réglages sur chaque bloc : Afficher seulement si (XPath), un prédicat sur la fiche (./Lifecycle/status = 'ACTIVE'), et Masquer à la création d'une fiche.

5. Le bloc « Rapport de validation »

Il affiche le rapport de validation de la fiche tel qu'EBX le calcule à partir des contraintes et des règles du modèle : rien à configurer côté données.

  • choisissez les gravités affichées (erreurs, avertissements, informations), le regroupement (par gravité, par onglet, aucun) et le nombre de messages avant « autres » ;
  • chaque message dit où se trouve le champ sur cette fiche (Vue d'ensemble › Fidélité › Points) et, avec Aller au champ, ouvre le bon onglet et met le champ en évidence ;
  • boutons d'action : un bouton n'apparaît que si un message porte sur le champ, le groupe ou l'association choisis, et ouvre l'endroit où l'on corrige (par exemple Ajouter une adresse pour une adresse de facturation électronique manquante) ;
  • Masquer le bloc quand le rapport est vide.

Les messages arrivent dans la langue de l'utilisateur. Un message rédigé dans une seule langue (une règle de validation DMA saisie en anglais) s'affiche dans la langue par défaut de l'instance, puis en anglais.

6. Les langues

Chaque texte saisi (libellés d'onglets, titres, notes, libellés de boutons, textes d'aide, libellés de champs) a une valeur par langue de l'instance. Choisissez la langue dans Langue et saisissez ; un soulignement en pointillé marque un texte non traduit dans la langue affichée. Traductions liste tous les textes de la fiche avec ce qui manque par langue, et Seulement les textes à traduire restreint la liste. Un texte absent dans une langue s'affiche dans la langue par défaut. Les libellés du modèle et les messages de validation viennent d'EBX, déjà traduits.

Les écrans du designer lui-même sont en français ou en anglais, selon la langue de l'utilisateur.

7. Enregistrer, déclarer, utiliser

  • Enregistrer écrit la mise en page (JSON) comme nouvelle version dans LayoutDesigner/FormLayout. Elle s'affiche à la prochaine ouverture d'une fiche, sans redémarrage, dès que la table déclare la fiche conçue.
  • Déclaration dans le modèle (onglet du bas) :
  • modèle packagé dans un module : Déclarer la fiche conçue sur cette table écrit la ligne recordForm dans le XSD, avec une copie de sauvegarde ; redémarrez le serveur une fois. Remettre la fiche précédente l'annule (nouveau redémarrage) ;
  • modèle DMA : déclarez com.on.ebx.layout.runtime.ConfigurableForm comme formulaire de la table dans l'écran du modèle (ou avec l'opération MCP set_form_layout du serveur data-model) et republiez ; pas de redémarrage.
  • Classe Java figée : la même mise en page écrite en classe UIForm ordinaire, pour un projet qui ne veut pas du designer à l'exécution. Facultatif.

8. Pour les développeurs : composants enregistrés

Un module peut ajouter son propre bloc. Implémentez com.on.ebx.layout.runtime.LayoutComponent (getLabel(Locale), write(UIFormPaneWriter, UIFormContext, JsonNode block, Locale)) et enregistrez-le une fois au démarrage :

LayoutComponents.register("acme.creditScore", new CreditScoreComponent());

Il apparaît alors dans la palette sous Composants enregistrés ; le runtime ouvre un panneau avec le titre et la note du bloc, et le composant écrit à l'intérieur. Le module n'a besoin du jar runtime qu'à la compilation (il est dans celui du serveur à l'exécution).

9. Limites (1.0.0)

  • Modèles DMA : le designer ne sait pas écrire la déclaration et ne la détecte pas ; son onglet Déclaration continue d'afficher les instructions DMA même quand la table est déclarée. Vérifiez sur la fiche elle-même.
  • Aller au champ suppose un message rattaché à un champ. Une règle posée sur la table (une contrainte sur plusieurs champs) porte sur la fiche entière : le message s'affiche, sans emplacement ni lien. Un bouton d'action lié à un champ n'apparaît donc jamais pour une telle règle.
  • EBX n'évalue pas une règle de champ sur un champ vide : une règle « courriel ou mobile » se pose sur la table.
  • La carte est uniquement OpenStreetMap (une iframe) : le navigateur de l'utilisateur doit joindre openstreetmap.org.
  • Une condition impossible à évaluer (un XPath faux) laisse le bloc affiché et écrit un avertissement dans kernel.log.
  • Une mise en page par table et par modèle : tous les datasets du modèle la partagent.
  • Vu tourner sur EBX 6.3.0-rc2 uniquement, avec les langues en-US, fr-FR et it-IT.
