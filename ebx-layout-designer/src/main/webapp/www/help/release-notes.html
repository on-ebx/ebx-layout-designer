Layout Designer for ON EBX: release notes

1.20.0 (2026-10-15)

  • Cards or list, the user's choice. The configurator lists the layouts users may switch between (card.layouts); the page shows a switch and remembers the choice per user.
  • ↑/↓ button next to the sort: the user reverses the chosen sort.
  • Page header: a create button opening EBX's creation form (only for users EBX lets create), and links to other tables of the dataset (filtered, with a service, in the current perspective) or to an address.
  • Linked records buttons ("Contacts 2", "Subsidiaries 1"): EBX's own table view of the linked records, filtered on the card's record; hidden when there is none.
  • Dates relative to today in conditions (days: "LEIs to renew within 90 days", "expired").
  • Groups: records under a heading per value of a field (sector, country…), with the group's count. The heading of the records without a value can be renamed (group.emptyLabel).
  • A condition on a Match and Merge linked field (state, golden, suspects…) now combines with a computed value: SQL reads it in the metadataset. Before, such a flag was dropped without a message.
  • Fixes found reproducing the Companies explorer: a tree row that is its own parent (NACE sections) is a root (values were indented 12 levels); a header link with a blank table opens the explorer's own table (it was not drawn).

1.19.0 (2026-10-15)

  • Freshness chosen by the explorer's configurator. On demand (the default): computed results are shared and kept until someone presses Refresh or until a maximum age (60 minutes by default); the page says when they were computed and warns when data changed since. Automatic: recomputed as soon as a table read changes, for small volumes or few users. Set in the designer, explorer settings (freshness in the explorer's JSON).
  • Two steps: count, records and tiles come first, the facets right after in a second request.
  • Collapsed facets are not counted until their box is opened.
  • A request replaced by a newer one stops on the server (search-as-you-type no longer queues work nobody reads).

1.18.0 (2026-10-15)

  • Explorers ask EBX for every answer. The explorer no longer reads the whole table into memory: each search, facet, tile, sort and page becomes an EBX XPath predicate run by a Request with the user's session (EBX's own index), or an EBX SQL statement when a computed value is involved (a count or a value read through a linked table, Match and Merge suspects through the add-on's metadataset). Nothing to build at the first opening, a change made in EBX shows in the next answer, and the explorer gets faster whenever EBX's engine does. Measured on 576,692 persons before the change: 15 s for the first opening, 2 to 15 s per action.
  • Text search compares like EBX (case-insensitive substring; accents count). A lookup with prefer now takes the smallest value among the preferred linked records. A provided (Java) value shows on cards only.
  • The statements of one page are sent to EBX at the same time (the explorer's own pool, the user's session shared as Insight's profiling does), and EBX's answers are kept a minute: shared between users who see every record (EBX checks it), per user otherwise, one computation when several users ask the same thing at once. 200 simultaneous users on 576,692 records: median 2.5-4 s once answers are kept, against 47-519 s without.
  • Text filters in SQL without CAST/ESCAPE so EBX's index serves them (editor's advice: 4 s to 0.1-0.4 s); suspects in SQL as one IN over a UNION. Under a filter, a long list of values says "more than N" instead of counting them.
  • Rights checked with test accounts on a copy: records hidden by a record rule, hidden fields and a hidden linked table never show in counts, facets, searches or cards; users with restricted rights never share answers.
  • Administrators: explain=1 (each statement sent to EBX and its time), route=sql, parallel=0, and a load test.

1.17.1 (2026-10-14)

  • A layout that names something gone is reported. A field removed from the model, a table or association that no longer exists, a workflow publication no longer published, a registered component no longer registered: the FormLayout record now carries a validation message for each (error for a field or a table, warning for the others; constraint LayoutValidation on layout, never blocks a save). The designer counts them in the top bar (N reference(s) to check), marks each block concerned with a red tag, shows a removed field of a panel as a red row with a remove button, and lists them all with Go to block and Remove.
  • At run time a gone reference stays silent: a removed field is left out of the facts block (it used to show its raw path), and a service button whose service no longer exists for the record is not drawn (it used to answer "Access denied").
  • The map's inspector note no longer mentions the old per-display lookup limit.

1.17.0 (2026-10-14)

  • Conditions tied to workflows, on any block and on each button of an Actions block (inspector, Depending on workflows; layout key "wf"): show it only outside a workflow task or only inside one (Session.isInWorkflowInteraction), and hide it, or show it only, while a workflow instance is running for the record (one publication or any, through the variables that hold the record's XPath or key). Example: no "Change bank details" button inside a task, nor while a bank-details change is already running for the supplier. The running instances are looked up once per display; the Workflows in progress block now shares that lookup.

1.16.0 (2026-10-14)

  • Explorers: a search page over any table, drawn like a form. A new service, Design the explorer (Actions menu of any table, administrators), draws a page with a search box, facets (values of a list field, flags raised by conditions, ranges of a number, a tree, the user's favorites), tiles that filter in one click, sorts, and one card per record. Every attribute of a card is chosen and set by clicking it: field or computed value, widget (text, pill or coloured dot, amount, gauge bar or ring, stars, relative date, flag of a country, link to the linked record…), colour per value, area of the card, roles; the card also takes an image from a DAMA media field, an edge coloured like its pill, three layouts, and buttons (open, favorite, workflow, service). Variants by role, every text in every locale. The explorer is stored in the new table ExplorerLayout (several per table possible) and shown by the service Explorer (ebx-layout-designer@Explorer, parameter ldxExplorer), for a perspective action; a saved change shows at the next opening, no restart. Format: docs/EXPLORER-FORMAT.md.
  • Built for volume. The page never receives the whole table nor a whole list of values: the server keeps one index per dataset and explorer (rebuilt when a table it reads changes), counts, filters, sorts and pages there, and sends one page of cards and, per facet, the most frequent values (10, then 10 more up to 50, then a search). Computed values (a count of linked rows, a value of a linked row, duplicates of a value, the Match and Merge suspects, a value given by a module through ExplorerValues.register) are read once per index build, one read per linked table.
  • EBX permissions in every case. Each user gets their own view of the index: the records come from a request run with their session (record access rules, model permissions), the fields they may not read are tested per table and per record; a facet, a flag, a tile, a sort, a searched field or a card attribute reading a hidden field is removed for them, counts and tiles only cover what they see, and every AJAX call re-checks the record it names. A workflow button shows only to who may launch the publication.
  • Favorites are kept in the new table ExplorerFavorite, per user, explorer and dataset.
  • The module's data model gains two tables: one server restart is needed after the upgrade (as for any change of the module's model).

1.15.2 (2026-10-14)

  • An image gallery can show whole images. The image gallery block cut every image to a square thumbnail, so a wide image (a product's tagline banner) lost both ends of its text. A new setting, Framing (fit in the layout), keeps the square thumbnails by default (cover) or shows each image whole, at its own proportions, up to 360 px high (contain).

1.15.1 (2026-10-13)

  • The designer warns when a map is computed from the address. In the inspector of a map or sites on a map block whose latitude and longitude fields are empty and whose address fields are set, a notice says that each unknown address is looked up in a geocoding service (one request a second at most on the public service) and kept in a cache, and advises latitude and longitude fields for many records. The same text is in the user guides and the format reference. A table of more than 1,000 rows placed by its address gets one WARN line in kernel.log per server start.
  • "Locate now" on a map waiting for positions. A map or sites on a map block whose addresses are not known yet shows a Locate now button: the browser asks the module (/ebx-layout-designer/geocode, with a ticket signed by the form, valid four hours, since that address does not see the EBX session) for each address in turn, at the service's pace, and places it on the map without reloading the form; an address not found falls back on its town. Positions found go to the same cache as the background lookups.

1.15.0 (2026-10-13)

  • A form never waits for the geocoding service any more. The map and sites on a map blocks placed an address without coordinates by asking Nominatim while the form was being drawn: about 0.8 s per address plus the 1.1 s the public service asks between two calls, up to six addresses per form, and again after every restart (memory cache). Measured on EBX 6.2.3 on the supplier form: 0.7 to 6.2 s for a record opened for the first time, 0.5 to 0.8 s once its addresses were known. Now an address not known yet is looked up by one background thread and shows "position being looked up"; it is placed at the next opening. Positions found are kept in a file (<ebx.home>/layout-designer-geocache.tsv, property ebx.layout.geocoder.cache, off to disable) and read back after a restart.

1.14.0 (2026-10-13)

  • An "Actions" block (palette, category Actions): buttons that launch a workflow on the record, or open a service on it. A workflow button shows only to who may launch the publication; it asks for confirmation in EBX's pop-up, launches the workflow as the user with the record's XPath in the chosen variable, and opens the first task, inside the perspective. EBX 6.3's own workflow launchers do not show in the record's Actions menu; this block puts the launch on the form. Each button can take a colour and an XPath condition, and one request at a time per record: while a request launched for the record is still running, the button opens its task (shown, not taken) instead of launching another.
  • A panel's colour can follow the record (inspector of a panel, Colour by a condition; layout key toneIf: an XPath predicate, the colour when true and the colour otherwise). One panel can turn red on an anomaly and green otherwise.
  • A native grid outside the first tab now loads when its tab is opened by default, as "lazy": true did since 1.11.0; a grid can still be built with the form by unticking the option ("lazy": false). On EBX 6.2 each native grid costs about a second of server rendering. Grids shown as cards are not affected.

1.13.0 (2026-10-13)

  • A panel can take a colour (inspector of a panel, Panel colour; layout key "tone": ok, warn, bad, info, accent, muted, the tones of the badges). The panel gets the tone's background, a border of its colour (thicker on the left) and a title in that colour, so that a panel shown only when something is wrong (a cond) stands out from the others. None keeps the white panel.
  • The changes block no longer lists a date and time that only differs by milliseconds: shown to the second, both sides read the same (a value written with milliseconds, then saved again through a form, which drops them). A difference of a second or more is still a change, as in EBX's own comparison.

1.12.0 (2026-10-13)

  • Del removes the selected block or field in the designer, like the inspector's Remove button and the bin: select it and press Del (Backspace on a Mac keyboard). Undo puts it back. The key does nothing while typing in a field of the inspector, in Preview mode, or when a tab or a row is selected.

1.11.1 (2026-10-13)

  • The creation form of a loaded-on-opening grid is no longer cut. In 1.11.0 the frame measured the position of what it showed; a record form fills its frame (its buttons are anchored to the bottom), so the frame kept the height of the grid (about 200 px) and the form opened by the "+" was cut. The frame now grows by what a scrolling area inside it hides, keeps its height while a form is shown, and goes back to the grid's height when the form is closed.

1.11.0 (2026-10-13)

  • A grid can be loaded when its tab is opened (inspector of a grid block, Load when its tab is opened, layout key "lazy": true; optional "height", in pixels, before the frame fits its content). The form no longer builds that native grid when it opens: the block shows a placeholder, and the first time its tab becomes visible a frame loads a page that draws this grid alone (module service LayoutGrid, never in a menu), with EBX's own toolbar, "+", filter and paging; the "+" creates a row already linked to the record. The block's and the tab's counters follow a row added or removed in the frame (Data Services …/<association>:count, with the user's permissions), and the frame fits the height of what it shows (a short grid, an open creation form). Measured on EBX 6.2.3 on a supplier form with five grids: about 0.75 s of server rendering instead of about 5 s (each native grid costs about 1 s on 6.2.3, much less on 6.3). A grid the user may not see (role, EBX permission) is not drawn in the frame either.

1.10.2 (2026-10-12)

  • A bin to remove a block or a field (contributed by Christian Mayor, PR #1): drop a block or a field on the bin at the bottom right of the designer to remove it from the form; a whole block can now be dragged by its body, not only by its tag. Undo puts it back. The bin is hidden in Preview mode.

1.10.1 (2026-10-12)

  • EBX permissions are applied to every block, not only to the fields. Fields have always gone through EBX's own widgets, which apply the user's permissions; the blocks around them read values through the Java API, which does not, so a header, key figures, a display widget, the history, the changes, values by source, a validation message, the rows of an association or a linked record could show a value the user may not read. Every read now asks EBX (SessionPermissions.getNodeAccessPermission / getAdaptationAccessPermission): a field the user may not read is left out of a panel and of every list, a record they may not see is left out of rows, counts, the hierarchy and "Used by", and a block whose fields are all out of reach is not drawn at all; Arrange my form does not even name such a block. Checked on EBX 6.2.3 with a buyer account and dataset permissions hiding a group, one field of a panel and one field of another tab. The designer itself is for administrators only.

1.10.0 (2026-10-12)

  • Who sees what, by role. By default nothing changes: everyone sees the whole form. A tab, block or field can now be made visible for some roles only, or read only for some roles (inspector › Who sees it, roles picked from EBX's directory or typed). A user who may not see a part does not get it at all: a hidden tab takes its blocks, a panel whose fields are all hidden disappears. Administrators see everything unless the layout says otherwise. This arranges the form only: EBX permissions still protect the data.
  • Variants of a form. A layout can hold whole forms for some roles (Form › + New variant, or Profiles and variants › Duplicate as a variant), in priority order: each user gets the first variant they have a role for, else the standard form. Profiles and variants lists them, shows who gets which form and a Who sees what table.
  • Preview as a role or a user of the directory: in Design mode what they do not see is struck through, in Preview mode it disappears and the canvas switches to the variant they would get.
  • Arrange my form. When the layout allows it, every user can arrange the form for themself: order of the tabs, the tab opened first, blocks hidden, folded or pinned to a first tab My essentials. A button on the form and an entry of the record's Actions menu open it in EBX's pop-up. The arrangement is laid over the layout, never a copy, so a later change in the designer still reaches everyone; Always shown keeps a tab or block out of reach; nothing is hidden while a record is created. Stored in a new table UserFormPreference of the module's dataset (the module's model changes: one restart after installing).
  • Tabs now keep a stable id in the layout. Format additions: roles, roRoles, locked, personal, adminSeesAll, variants (docs/LAYOUT-FORMAT.md, Who sees what).
  • An empty My essentials tab says why: every pinned block has a display condition the record does not meet.
  • build.sh compiles the module against the runtime it has just built, ahead of any older runtime jar in the server's lib. tools/test.sh runs the checks that need no server.

1.9.0 (2026-10-12)

  • New block "Value over time" (palette › Time): the successive values of one or more fields, read in the table's history, one tab per field. A number gets a curve (steps, or a line), its current value and the change since the first value; the list of changes gives the date, old → new value and the author ("automatic process" for EBX's system user). A value that never changed says so instead of drawing a flat line. Period: the whole history, 12 months or 90 days.
  • New block "Sites on a map" (palette › Location): the rows of an association (establishments, addresses) on an OpenStreetMap map, with their list beside it; a click on a site centres the map on it, zoom and drag work. A row is placed by its latitude and longitude, else by its address (the EBX server asks Nominatim, at most six new addresses per display, answers kept in memory); an unknown street is placed on its town and flagged. A yes/no field highlights the head office, another hides inactive sites.
  • New block "Values by source" (palette › Quality): on a golden record of the Match and Merge add-on, the value each merged source gave, field by field, the value kept highlighted; by default only the fields where sources differ, the key left out. A merged record links to its golden. Public API of the add-on, called so that a form works without it.
  • New block "Workflows in progress" (palette › Actions): the workflows whose variables point to the record (its XPath or key), on every publication and its earlier versions: label, start, current tasks with who holds them and since when. The user's own task opens in EBX's pop-up inbox; someone else's opens in the monitoring view.
  • New block "Translations" (palette › Quality): for each language, the share translated and the missing fields, from a translation table (a row per language, expected languages reported at 0 % when absent) or from fields of the record.
  • New block "Inheritance" (palette › Quality): in a child dataset, the fields changed here with the parent's value, and those that follow the parent; "created here" when the parent does not have the record.
  • Activation, clearer: the state of the form is now a banner under the designer's header, always visible, with the next action as its main button: not used yet (Activate), activated and waiting for EBX's restart, DMA model, or active. "See the steps" opens a step-by-step guide. For a DMA model it gives the class to copy, where to declare it in the model's component library (Component name, Configuration › Rule), where to choose it for the table (Form layout › Component), then Publish; for a module model, the line written into the XSD and why a restart is needed; when the designer cannot write the file, the line to paste by hand.
  • The designer knows when the form is really used: the form reports each table it is drawn for, so the banner turns green ("last drawn on … on …") for a DMA model too, where nothing else tells it (in memory, since the server started).
  • The history reading is shared by the "Change history" block and the new one.

1.8.1 (2026-10-12)

  • Hierarchy chart: up to six subsidiaries sit centred under the record, each hung on the line like an org chart (they were packed to the left); cards no longer overlap their neighbour.

1.8.0 (2026-10-12)

  • New block "Hierarchy chart" (palette › Relations): the group the record belongs to, through a foreign key to the parent in the same table. Three layouts, switchable on the form: an org chart centred on the record (its ancestors above with the number of other entities beside them, the record with its counts, its direct subsidiaries as cards, one more level on demand), a tree of the whole group, opened down to the record, with a search, and rings (one per level, slices sized by the entities below, the record's path solid). In automatic mode the org chart becomes the tree beyond 24 direct subsidiaries. A line under the name and a colour by value (tones, or automatic colours) are chosen in the designer. A click opens the entity's record in EBX's pop-up over the current one, so closing it comes back to the record and the tab (or, as chosen, instead of the current record, or in a new tab). The table is read once into a key → parent index kept until the table changes, then only the group's records (up to 2,000) are read.

1.7.0 (2026-10-11)

  • Map from an address: the map block takes address fields in order (number, street, postcode, city, country…). When latitude or longitude is empty, the EBX server asks OpenStreetMap's search (Nominatim) for the position of the address and the map says so under it. Answers are kept in memory, calls spaced by more than a second as the public service asks; -Debx.layout.geocoder.url=<url> points to another Nominatim, =off never sends an address out.
  • Change history: a change of many fields at once (an enrichment, an import) shows "N fields", the detail one click away. Sum up beyond N changed fields (summarizeAbove, 6) sets the threshold, 0 never sums up.

1.6.2 (2026-10-11)

  • Contacts block: wider cards (320 px minimum, cardWidth to change it) so that a name and an e-mail address stay on one line, and no more breaking in the middle of a word. max sets how many contacts are shown (60 by default, as before); when there are more, the block now says so instead of cutting the list silently.

1.6.1 (2026-10-09)

  • Change history: a creation now shows who and when only, not every value of the new record (they are the form itself). List the values at creation (creationDetails) brings the old display back.

1.6.0 (2026-10-09)

  • New block "Changes in this request" (palette › Quality): in a child dataspace (a workflow's work dataspace), what the record changes compared with the reference, field by field (old value struck through → new value), or "created in this request". Compares with the reference as it was when the request was created (default) or as it is now. Public API DifferenceHelper.compareOccurrences.
  • New block "Used by" (palette › Relations): the records of other tables (and other datasets) that point to this one, counted per table and field, with a few examples. Public API SchemaNode.getRelationships(dataset, session), filtered by the user's permissions.

1.5.0 (2026-10-09)

  • New block "Record information" (palette › Time): who created the record and when, who changed it last and when. Each of the four items can be hidden, the block shows as a grid or on one line, with "3 days ago" if wanted. The values are those EBX keeps for every record (Adaptation.getCreator, getTimeOfCreation, getLastUser, getTimeOfLastModification), user names through the directory: nothing to set up in the model. The designer's preview shows the real values of the record chosen.

1.0.0 (2026-10-07)

First release.

  • Designer (service Design the record form, on every table, administrators only): tabs, one- or two-column rows, blocks placed by drag and drop, a record of the table as live preview, an inspector, one input per instance locale for every text, a Translations view listing what is missing.
  • Runtime (ConfigurableForm, a UIForm in the server's lib): reads the table's active layout at each display, so a saved layout shows at the next opening of a record, with no restart. Without a layout the standard EBX form shows.
  • Blocks: panel of native field rows, identity band, key figures, validation report, association (native EBX grid or cards), map (OpenStreetMap), group structure, Match and Merge state, help text, registered Java component. Any block can be conditioned by an XPath predicate on the record and hidden on creation.
  • Validation report block: the record's own EBX validation report, by severity, each message located (tab › panel › field) with a Go to field link that opens the right tab. A message written in one locale only falls back on the instance's default locale.
  • Record form layouts page: saved layouts, and the choice of a dataspace, dataset and table with EBX's own selectors to start a new one.
  • Declaration in the model: for a model packaged in a module, the designer writes the recordForm line in the XSD (with a backup) and can put the previous form back. For a DMA model, the class is declared in the model screen (or with the data-model MCP operation set_form_layout) and the model republished.
  • Public EBX Java API only; no MCP server needed; Java 11 bytecode.

Seen running on EBX 6.3.0-rc2 (FastTrack): the module model Companies (73 fields, 11 associations) and a DMA model of B2C customers (3 tables, three validation rules of each severity).

Known limitations: see docs/USER-GUIDE.md, section Limitations.
